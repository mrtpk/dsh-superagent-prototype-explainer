Purpose

This page is a lookup reference, not a tutorial. It covers four things: how the bundle loads into a DeepSeek Harness (DSH) profile, each settings block's fields and defaults, the execution environment variables, and the {{term management-api | Management API}}. The panel and scripts/dsh-superagent both call that API. For installing a working deployment step by step, accounts, and troubleshooting, see the repository's own {{cite docs/006-deployment.md}}.

How the bundle loads into a DSH profile

dsh-superagent ships as a {{term dsh-bundle | DSH bundle}}: package.json's dsh.bundle.patch field names cordis.patch.yml ({{cite package.json:30-33}}). When a DSH profile stacks the bundle, DSH applies this patch before the profile's own patch file. The sibling site's "Profiles and bundles" explains bundles, patch layers and their order.

cordis.patch.yml inserts three plugins ({{cite cordis.patch.yml:4-12}}) and two agent presets ({{cite cordis.patch.yml:20-23}}, {{cite cordis.patch.yml:125-128}}):

Insert idLoads (export path)What it is
dsh-superagentdsh-superagent (the package's main entry)The main plugin: mounts Runtime ({{cite src/index.ts:7}}, {{cite src/index.ts:21}}).
dsh-superagent-githubdsh-superagent/github-watchThe GitHub {{term source | Source}}'s own Cordis plugin, name = 'dsh-superagent-github' ({{cite src/sources/github.ts:110-112}}). Its row has no disabled key, so it starts enabled ({{cite cordis.patch.yml:7-8}}).
dsh-superagent-feishudsh-superagent/feishu-watchThe Feishu Source's plugin. Ships with disabled: true ({{cite cordis.patch.yml:10-12}}); enabling it still needs a bot CLI configured, {{cite docs/006-deployment.md:49-69}}.
dsh-superagent-worker-preset, dsh-superagent-router-preset@deepseek-ai/dsh-agent-preset (two rows)The two agent presets Sessions load by id, WORKER_PRESET and ROUTER_PRESET ({{cite src/app/sessions.ts:48}}). Removing either row makes a resume fail with agent-preset/not-found ({{cite docs/006-deployment.md:244-246}}).

Each export path is a separate build output: tsdown.config.ts compiles src/index.ts, src/sources/github.ts and src/sources/feishu.ts into three separate files under lib/ ({{cite tsdown.config.ts:10}}), matching the paths that package.json's exports field declares ({{cite package.json:11-18}}). The panel is a fourth, separate build, a browser bundle loaded into DSH's own module loader ({{cite tsdown.config.ts:11-13}}); {{link concepts/panel-and-management-api}} covers how it is injected.

The profile that loads the bundle needs its own patch file. That file sets the plugin's required stateDir, and the host and port of DSH's web server, which serves the panel. {{cite examples/profile.cordis.patch.yml}} is a worked example. stateDir must be an absolute path ({{cite src/deployment.ts:13}}, {{cite src/deployment.ts:16}}). The bundle's own comment says that the plugin refuses to start without it ({{cite cordis.patch.yml:1-3}}). Three more machine fields are Volatile: dsh-superagent reads them again on each use, so a change applies without a restart ({{cite src/deployment.ts:14}}, {{cite src/deployment.ts:17-22}}).

Execution environment variables

These DSH_SUPERAGENT_* variables make up a {{term ticket | Ticket}}'s execution environment. The prepare command gets them as real environment variables ({{cite src/executor/dsh.ts:251-254}}). The worker gets them as a list in its system prompt, not as variables of its shell ({{cite src/app/sessions.ts:247}}, {{cite src/app/prompts.ts:83-84}}). None of them is a credential. DSH strips a variable whose name has KEY, PASSWORD, SECRET or TOKEN from a child process environment ({{cite src/infra/environment.ts:3}}).

The scripts/dsh-superagent CLI

scripts/dsh-superagent is a 250-line Python script, with the shebang #!/usr/bin/env python3 ({{cite scripts/dsh-superagent:1}}). It still manages the service through tmux, but the file itself is Python.

It runs one DSH service process per profile, without disturbing any other tmux session ({{cite scripts/dsh-superagent:2}}), inside a tmux session named dsh-<profile> ({{cite scripts/dsh-superagent:160}}). It takes one of four actions:

ActionWhat it does
statusPrints process ids, health and setup problems as JSON, and returns the exit code below ({{cite scripts/dsh-superagent:122-129}}).
startIf the service does not run, starts it in a new tmux window, or in a new tmux session when none exists. Then it polls GET state until the runtime is up or the timeout passes ({{cite scripts/dsh-superagent:159-206}}).
stopSends SIGINT and waits for a graceful shutdown. It also records an intentional-stop marker, so a monitor that uses --respect-stop skips later starts ({{cite scripts/dsh-superagent:132-148}}).
restartRuns stop without the marker, then start ({{cite scripts/dsh-superagent:237-241}}).

The flags are below. Only --profile and --url read an environment variable for their default:

FlagDefaultMeaning
--profile$DSH_SUPERAGENT_PROFILE, or superagentWhich DSH profile to control ({{cite scripts/dsh-superagent:212-213}}).
--url$DSH_SUPERAGENT_URL, or http://127.0.0.1:3082Where to read GET state for a health check ({{cite scripts/dsh-superagent:214-215}}).
--timeout60 secondsHow long start waits for the runtime to become ready ({{cite scripts/dsh-superagent:216}}).
--stop-timeout300 secondsHow long stop waits for a graceful shutdown, while running Executor Sessions finish their step ({{cite scripts/dsh-superagent:217-218}}).
--respect-stopoffFor a monitor: skip start or restart while an intentional stop is active ({{cite scripts/dsh-superagent:219-220}}, {{cite scripts/dsh-superagent:232-234}}).

status, start and restart share one exit-code scheme, computed by outcome() ({{cite scripts/dsh-superagent:112-119}}):

CodeMeaning
0The service runs normally: none of the other three conditions below held ({{cite scripts/dsh-superagent:118-119}}).
1It does not run, runs twice, does not answer, or its runtime health entry is not ready or paused ({{cite scripts/dsh-superagent:114-115}}, {{cite scripts/dsh-superagent:102-104}}). The script also exits with 1 on an error such as a start timeout ({{cite scripts/dsh-superagent:246-250}}).
2It runs, but some other part reports an error ({{cite scripts/dsh-superagent:118-119}}, {{cite scripts/dsh-superagent:107-109}}). A restart does not fix this.
3It runs and waits for setup ({{cite scripts/dsh-superagent:116-117}}). A restart does not fix this either.

The CLI reads GET state, a route that the panel also reads, with the same marker header, x-orchestrator-request: 1 ({{cite scripts/dsh-superagent:81-84}}, {{cite src/client/api.ts:37}}). {{link concepts/panel-and-management-api}} covers why that header is required.

The Management API

{{link concepts/panel-and-management-api}} covers the loopback and same-origin checks, and how a save versions against one block. This table is the route list itself, from routes() ({{cite src/app/http.ts:151-214}}).

RequestWhat it does
GET stateSetup, health, load and pause state; read by the panel and by scripts/dsh-superagent status ({{cite src/app/http.ts:104-109}}, {{cite src/app/http.ts:156}}).
GET overviewThe Overview tab's summary ({{cite src/app/http.ts:157-158}}).
GET searchSearches Triggers, Threads and Tickets; it also matches a cached Feishu message link ({{cite src/app/http.ts:159}}, {{cite src/app/views/threads.ts:55-58}}).
GET sourcesEach Source's status and health, and the last day's filtered Triggers and dropped messages ({{cite src/app/http.ts:160}}, {{cite docs/006-deployment.md:173}}).
GET settingsEvery settings block, each Source instance, the Policy version and the execution environment ({{cite src/app/http.ts:161}}).
POST sources/:id/labelsReads one Source's display names again, such as Feishu chat names ({{cite src/app/http.ts:162}}, {{cite src/app/settings.ts:254-258}}).
GET threads, GET threads/:keyLists or opens one Thread's detail ({{cite src/app/http.ts:163-172}}).
POST threads/:key/unsubscribeRemoves every Ticket's Subscription to one Thread ({{cite src/app/http.ts:173-176}}, {{cite src/core/tickets.ts:214-218}}).
POST triggers/:id/requeueQueues a stored Trigger for a fresh Eval ({{cite src/app/http.ts:177-181}}).
GET decisions, POST decisions/:id/dismissLists Decisions, or dismisses one ({{cite src/app/http.ts:182-187}}).
GET tickets, GET tickets/:idLists Tickets, or one Ticket's full detail ({{cite src/app/http.ts:188-192}}).
POST tickets/:id/retry, POST tickets/:id/stopRetries or stops a Ticket, as the panel does ({{cite src/app/http.ts:193-194}}).
POST executor/pausePauses or resumes processing ({{cite src/app/http.ts:195}}).
PUT settings/:blockSaves one settings block against the revision it read ({{cite src/app/http.ts:196-202}}).
GET policy/historyPast Policy versions ({{cite src/app/http.ts:203}}).
POST policy-sync/:idRe-syncs one Source's allowed list now ({{cite src/app/http.ts:204}}).
POST setup/checkRestarts dsh-superagent to run setup again. It refuses when setup has nothing to fix ({{cite src/app/http.ts:205}}, {{cite src/app/setup.ts:54-57}}).
GET modelsThe model catalog a settings form's model picker reads ({{cite src/app/http.ts:206}}, {{cite src/client/settings-kit.tsx:74-82}}).
GET prompts, PUT promptsReads or saves the prompt configuration, against its own revision ({{cite src/app/http.ts:207-211}}).
POST prompts/previewComposes both roles' prompts without saving ({{cite src/app/http.ts:212}}).

A request needs the 127.0.0.1 or localhost host with the web server's port, the x-orchestrator-request: 1 header, and no foreign Origin ({{cite src/app/http.ts:75-79}}). A request that fails this check gets 403 ({{cite src/app/http.ts:237}}). Other refusals use a plain status code: 400 for an invalid request, 404 for something missing, 409 for a stale revision, 500 for anything else ({{cite src/app/http.ts:81-91}}).

This table leaves out each response's exact JSON shape. src/app/api.ts types every route's parameters and response, shared by the server and the panel's browser bundle; the repository's own table of the routes that agents may rely on, with their fields, is {{cite docs/006-deployment.md:167-179}}.
