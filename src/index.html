{{project name}} is a proactive coding agent for one GitHub repository, packaged as a bundle for DeepSeek Harness, DSH ({{cite README.md:7}}). It runs inside a DSH profile, as a set of Cordis plugins ({{cite package.json:30-32}}). The sibling site, DeepSeek Harness Explained, teaches Cordis and DSH on their own. This site explains only what dsh-superagent adds on top of them. This site explains the code at commit {{project short_sha}}. You need to know TypeScript and Node. You do not need to know this project's domain model yet: {{link learn/what-this-is}} teaches it.

What it doesListens to GitHub (and, optionally, Feishu); when an allowed person asks for work, it opens a {{term ticket | Ticket}} and works on it in its own agent Session and directory ({{cite README.md:7}}).
Runs onNode.js, inside a DSH process, as the Cordis plugin dsh-superagent that one DSH profile loads ({{cite src/index.ts:1-7}}).
Code sizeTypeScript and TSX across src/, plus prompts and skills; the project has an unusually large test suite, indexed by its own test table ({{cite docs/007-architecture.md:406}}). See {{link code/index}}.
Run itSetup has many steps, so a coding agent does it with you, following the repository's own SETUP.md ({{cite README.md:13-17}}).

The system map

The map shows the main parts, and the order a GitHub event goes through them to become a Ticket and, later, a reply. Each title is a link. A grey link is a page not written yet.

  1. 1 · {{link concepts/sources-and-triggers | Source and Trigger}} — the GitHub Source polls and reads events, and turns each one into an immutable {{term trigger | Trigger}} ({{cite src/sources/github.ts:280-296}}, {{cite src/sources/github-trigger.ts:65-76}}).
  2. 2 · {{link concepts/policy-and-authorization | Policy, gate and Eval}} — the gate checks who may ask for work, and Eval turns an admissible batch into a Decision ({{cite src/policy.ts:191-211}}, {{cite src/core/evals.ts:71-119}}).
  3. 3 · {{link concepts/ticket-lifecycle | The Ticket}} — an accept Decision creates a Ticket under a {{term mandate | Mandate}}, with its first {{term assignment | Assignment}} ({{cite src/core/tickets.ts:37-56}}).
  4. 4 · {{link concepts/executor-and-worker-sessions | The Executor}} — the Executor launches a worker Session for the Ticket, in its own directory ({{cite src/executor/dsh.ts:264-266}}).
  5. 5 · The reply — a worker's report can send a reply back through a {{term channel | Channel}}, such as a GitHub comment ({{cite src/app/outbox.ts:27-32}}, {{cite src/sources/github-channel.ts:18-45}}).

Two parts sit beside every step, not inside the numbered path. A SQLite Store holds every Trigger, Thread, Decision, Ticket and Assignment the Engine writes ({{cite src/app/store.ts:1}}), and the durable {{term effect | Effects}} queue runs the launches, deliveries and replies each step enqueues ({{cite src/app/effects.ts:41-46}}). The React {{link concepts/panel-and-management-api | panel}} reads the same Store to show what needs a person ({{cite src/client/app.tsx:1}}).

The map shows one Ticket's path once. It leaves out retries, resumes, Policy changes and the Feishu Source, which follows the same Source contract as GitHub. The tour {{link tours/life-of-a-github-mention}} follows one real path stop by stop.

How to use this site

  • Levels. Each page has a level: Beginner, Intermediate or Advanced.
  • One depth per page. A page starts with a plain explanation and a diagram. Then it shows the real code, with one compact "More detail" section.
  • Check yourself. Most pages end with 3 to 5 questions. Click "Show answer" to see the answer.
  • Search. Press /, then type a word, a file name or a setting.
  • Glossary. Words with a dotted line, such as {{term ticket}}, have a short definition. {{link reference/glossary}} lists all terms.
  • Code. The build copies every code excerpt from the repository. Every citation opens the file at commit {{project short_sha}}.
