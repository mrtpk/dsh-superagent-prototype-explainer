Glossary

Referenceabout 9 min read

Code version: dsh-superagent @ 6337fc8 · 2026-10-31

This page lists every term that has a tooltip on this site. Each entry gives a short definition. Many entries link to a page with the full explanation.

A B C D E M O P R S T W

A#

accept mode also: accept-mode

The Policy setting that controls inferred candidates: off, observe (assess but never accept) or auto (assess and accept).

src/core/model.ts:99-103 is the type. Policy.admitsInferred (src/policy.ts:212) checks it against the matched rules. The default is observe (src/policy.ts:84).

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

admission also: gate, the gate, admission table

Eval's first, deterministic layer: it decides who may send a Trigger, with what strength, before any assessment runs.

src/core/ports.ts:20 is the Policy.gate method the Engine calls; src/policy.ts:191-211 is the implementation. It also reads the per-Source admission table, which src/policy.ts:138-140 looks up, with the defaults of src/admission.ts:12-13.

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

Assignment

The binding of a Ticket to one Executor instance. A Ticket has several over time. Its state is pending, running or ended.

src/core/model.ts:218-233 is the shape: its state, its latest Report, and when Inputs last reached it.

Read more: The Ticket lifecycle: stages, Assignments and Subscriptions

B#

built-in part also: built-in parts, prompt part

One named built-in text, such as runtime/admission or a Source skill, that a team may override with its own text.

src/app/prompts.ts:24-26 lists the 15 parts a team may override, by the key an override names them by.

Read more: Prompts and Source skills: how the system prompt is assembled

C#

Channel

The write side of a Thread: where a reply, acknowledgement or result goes back to the Source.

src/core/model.ts:9 is the type: a Source, a Thread and an address the Source's own format defines.

Read more: Source, Trigger, Thread and Channel: where work comes from

D#

Decision

The result of an Eval: accept, stop, ignore or unavailable, with its reasons.

src/core/model.ts:190-209 is the shape, recorded on the Thread by threadKey. The type also lists reopen, but evals.ts makes only the other four kinds (src/core/evals.ts:282-316).

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

DSH bundle

How dsh-superagent ships: a package with a Cordis patch file that a DSH profile loads, not a standalone program.

package.json:30-33 points dsh.bundle.patch at cordis.patch.yml:4-12, which inserts the three plugins.

Read more: What dsh-superagent is

DSH profile

A named DeepSeek Harness configuration and runtime. dsh-superagent runs in its own profile, separate from a person's own.

scripts/dsh-superagent:2 names the default profile, superagent; scripts/dsh-superagent:30-32 keeps each profile's control files apart.

Read more: What dsh-superagent is

E#

Effect

One durable row in the side-effect queue: an assessment, a launch, a delivery, a relay, a notice or a reply, run after its transaction commits.

src/app/effects.ts:11-24 lists the six kinds; src/app/effects.ts:42-46 describes the queue itself.

Read more: Effects and the Store: a durable queue, and one writer per state

Eval

The judgement on a batch of Triggers: a gate layer, then an assessment, ending in a Decision.

src/core/evals.ts:1 is the part that runs it; src/core/model.ts:136-154 is the Evaluation state it tracks on a Thread.

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

Executor

The port that runs Assignments. Its implementation keeps one Executor Session and one directory per Ticket.

src/core/ports.ts:55-69 is the port the Engine calls; src/executor/dsh.ts:207's DshExecutor is the only implementation in this repository (src/executor/dsh.ts:1).

Read more: The Executor and worker Sessions: one Session per Ticket, a concurrency limit

M#

Management API also: orchestrator API

The local HTTP API the panel uses, and that scripts and agents can also call, under one path prefix.

src/app/http.ts:230-237 registers the /orchestrator/api/ prefix on a loopback Web server, with a same-origin check.

Read more: Configuration and deployment: the bundle, settings, env vars, the CLI and the API

Mandate

What an accept grants: the strength, scope and Policy version a Ticket's work relies on. It never changes once set.

src/core/model.ts:125-133 is the shape. Only accept creates one; a person's stop withdraws it; failed revalidation revokes it (docs/002-authorization.md:129).

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

O#

Outbox

The Engine's port for Channel writes: it keeps a receipt for every outgoing message and sends it as durable work.

src/core/ports.ts:76-83 is the port; src/app/outbox.ts:22-52's Outbox class is the implementation, backed by a reply Effect.

Read more: Effects and the Store: a durable queue, and one writer per state

P#

Panel also: management panel, web panel

The React page dsh-superagent injects into DeepSeek Harness's own web sidebar, for supervising and configuring it.

src/client/index.tsx:49-58's apply() injects a sidebar icon, the main panel component and a Plugin Manager config view into DSH's own slots.

Read more: The panel and the Management API: tabs, routes and settings versions

Policy also: Policy version

The versioned rules for who may start work, and each Source's own part of those rules.

src/core/ports.ts:16-27 is the port the Engine reads: a version, a gate, Mandate revalidation and the accept-mode check.

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

prompt revision also: prompt version

One saved, numbered version of a role's prompt configuration: the team sections, overrides and skills, together.

src/app/prompts.ts:39-41 is the stored shape: a revision number, its predecessor, when and where it was saved, and the full configuration.

Read more: Prompts and Source skills: how the system prompt is assembled

R#

Report

What an Assignment reports back to its Ticket: progress, waiting, ready, blocked, failed or dropped.

src/core/model.ts:212-216 types the states; src/core/assignments.ts:10-20's WorkerReport is what a worker or the Executor itself sends in.

Read more: The Ticket lifecycle: stages, Assignments and Subscriptions

S#

settings block also: settings blocks

One named part of Settings, such as policy, executor or one Source, saved on its own with its own revision counter.

src/app/settings.ts:32-52 lists the block kinds; src/app/store.ts:188 keeps each block's own revision counter.

Read more: The panel and the Management API: tabs, routes and settings versions

Source also: Source kind, Source instance

A stream of events. A Source kind is a reusable plugin; a Source instance is one configured kind, such as one GitHub repository.

A kind declares its identity, configuration schema and health entries (src/sources/kind.ts:84-96). SourceRegistry resolves the instance of each installed kind (src/sources/registry.ts:44-53).

Read more: Source, Trigger, Thread and Channel: where work comes from

Source skill also: bundled skill, bundled Source skill

A bundled Skill that teaches the agents a Source's own tools, such as GitHub's gh CLI or reading a Feishu chat.

dsh-superagent bundles exactly two: skills/dsh-superagent-github/SKILL.md and skills/dsh-superagent-feishu/SKILL.md. Each is registered as a DSH Skill in every Session's skill scope, the Feishu one only when a Feishu bot is configured (src/app/prompts.ts:146-148, src/app/sessions.ts:319-324); see the sibling site's "Skills" for how DSH itself loads one on demand.

Read more: Prompts and Source skills: how the system prompt is assembled

stage

A Ticket's current wait: idle, working (plain or queued), person (delivery, answer, review, blocked or failed), or ended.

src/core/stage.ts:4-6 is the type; src/core/stage.ts:8-21's ticketStage computes it, row by row, from the Ticket's own stored facts.

Read more: The Ticket lifecycle: stages, Assignments and Subscriptions

Store

The one SQLite database that holds every domain aggregate, the effect queue and the Outbox's receipts.

src/app/store.ts:46-50 is the class; src/app/runtime.ts:90-93 locks the state directory before Runtime opens it, so a second process cannot write the same database.

Read more: Effects and the Store: a durable queue, and one writer per state

strength

How a Trigger was admitted: explicit, inferred, or not admitted (no Mandate at all).

src/core/model.ts:96 types the two Mandate-bearing values; src/core/ports.ts:7's GateResult shows the third case as admissible: false, which carries no strength.

Read more: Policy and authorization: the gate, Eval and the Mandate it grants

Subscription

The many-to-many link between Tickets and Threads. A Trigger on a subscribed Thread reaches every live subscribed Ticket.

src/core/model.ts:163-164 holds the list on the Thread; src/core/tickets.ts:417-422's subscribe adds to it, and src/core/intake.ts:34-52 fans a Trigger out through it.

Read more: The Ticket lifecycle: stages, Assignments and Subscriptions

T#

team section also: team sections

One of three prompt sections a team writes directly: Communication, Ticket scope and Delivery requirements.

src/app/prompts.ts:14-17 lists the three sections and the exact heading each one gets in the composed prompt.

Read more: Prompts and Source skills: how the system prompt is assembled

Thread

Triggers in time order. At most one Eval runs on a Thread at a time, and a Thread may carry several Tickets.

src/core/model.ts:156-182 is the aggregate: its Subscriptions, its running Eval (evaluating), and its queued Triggers.

Read more: Source, Trigger, Thread and Channel: where work comes from

Ticket

A unit of authorized work. Only an Eval's accept creates one; it goes open to ended and sometimes back to open.

src/core/model.ts:277-308 is the aggregate: its Mandate, Channels, Assignments and Inputs.

Read more: The Ticket lifecycle: stages, Assignments and Subscriptions

Trigger

One immutable event a Source produces, such as a GitHub comment or a Feishu message, with the Source's own metadata.

src/core/model.ts:22-39 defines the shape: every Thread it belongs to, its actor, whether a person wrote it, and whether it addressed the agent.

Read more: Source, Trigger, Thread and Channel: where work comes from

W#

worker slot

One unit of the Executor's concurrency limit. A Ticket holds one while its worker launches, runs a turn, or finishes background work.

src/executor/dsh.ts:165-199's WorkerSlots tracks them, with one extra slot for a wake for a person's message.

Read more: The Executor and worker Sessions: one Session per Ticket, a concurrency limit
