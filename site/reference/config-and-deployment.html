Configuration and deployment: the bundle, settings, env vars, the CLI and the API

Referenceabout 11 min read

Code version: dsh-superagent @ 6337fc8 · 2026-10-31

Purpose#

This page is a lookup reference, not a tutorial. It covers four things: how the bundle loads into a DeepSeek Harness (DSH) profile, each settings block's fields and defaults, the execution environment variables, and the Management API. The panel and scripts/dsh-superagent both call that API. For installing a working deployment step by step, accounts, and troubleshooting, see the repository's own docs/006-deployment.md.

How the bundle loads into a DSH profile#

dsh-superagent ships as a DSH bundle: package.json's dsh.bundle.patch field names cordis.patch.yml (package.json:30-33). When a DSH profile stacks the bundle, DSH applies this patch before the profile's own patch file. The sibling site's "Profiles and bundles" explains bundles, patch layers and their order.

cordis.patch.yml inserts three plugins (cordis.patch.yml:4-12) and two agent presets (cordis.patch.yml:20-23, cordis.patch.yml:125-128):

Insert idLoads (export path)What it is
dsh-superagentdsh-superagent (the package's main entry)The main plugin: mounts Runtime (src/index.ts:7, src/index.ts:21).
dsh-superagent-githubdsh-superagent/github-watchThe GitHub Source's own Cordis plugin, name = 'dsh-superagent-github' (src/sources/github.ts:110-112). Its row has no disabled key, so it starts enabled (cordis.patch.yml:7-8).
dsh-superagent-feishudsh-superagent/feishu-watchThe Feishu Source's plugin. Ships with disabled: true (cordis.patch.yml:10-12); enabling it still needs a bot CLI configured, docs/006-deployment.md:49-69.
dsh-superagent-worker-preset, dsh-superagent-router-preset@deepseek-ai/dsh-agent-preset (two rows)The two agent presets Sessions load by id, WORKER_PRESET and ROUTER_PRESET (src/app/sessions.ts:48). Removing either row makes a resume fail with agent-preset/not-found (docs/006-deployment.md:244-246).

Each export path is a separate build output: tsdown.config.ts compiles src/index.ts, src/sources/github.ts and src/sources/feishu.ts into three separate files under lib/ (tsdown.config.ts:10), matching the paths that package.json's exports field declares (package.json:11-18). The panel is a fourth, separate build, a browser bundle loaded into DSH's own module loader (tsdown.config.ts:11-13); The panel and the Management API: tabs, routes and settings versions covers how it is injected.

The profile that loads the bundle needs its own patch file. That file sets the plugin's required stateDir, and the host and port of DSH's web server, which serves the panel. examples/profile.cordis.patch.yml is a worked example. stateDir must be an absolute path (src/deployment.ts:13, src/deployment.ts:16). The bundle's own comment says that the plugin refuses to start without it (cordis.patch.yml:1-3). Three more machine fields are Volatile: dsh-superagent reads them again on each use, so a change applies without a restart (src/deployment.ts:14, src/deployment.ts:17-22).

Execution environment variables#

These DSH_SUPERAGENT_* variables make up a Ticket's execution environment. The prepare command gets them as real environment variables (src/executor/dsh.ts:251-254). The worker gets them as a list in its system prompt, not as variables of its shell (src/app/sessions.ts:247, src/app/prompts.ts:83-84). None of them is a credential. DSH strips a variable whose name has KEY, PASSWORD, SECRET or TOKEN from a child process environment (src/infra/environment.ts:3).

A Source gives its variables only while it is on (src/app/execution-environment.ts:31). declaredVariables() still lists a disabled Source's variables, marked enabled: false (src/app/execution-environment.ts:20-24). The settings view of the API serves this list (src/app/views/settings.ts:39).

The scripts/dsh-superagent CLI#

A Python script, not a shell script

scripts/dsh-superagent is a 250-line Python script, with the shebang #!/usr/bin/env python3 (scripts/dsh-superagent:1). It still manages the service through tmux, but the file itself is Python.

It runs one DSH service process per profile, without disturbing any other tmux session (scripts/dsh-superagent:2), inside a tmux session named dsh-<profile> (scripts/dsh-superagent:160). It takes one of four actions:

ActionWhat it does
statusPrints process ids, health and setup problems as JSON, and returns the exit code below (scripts/dsh-superagent:122-129).
startIf the service does not run, starts it in a new tmux window, or in a new tmux session when none exists. Then it polls GET state until the runtime is up or the timeout passes (scripts/dsh-superagent:159-206).
stopSends SIGINT and waits for a graceful shutdown. It also records an intentional-stop marker, so a monitor that uses --respect-stop skips later starts (scripts/dsh-superagent:132-148).
restartRuns stop without the marker, then start (scripts/dsh-superagent:237-241).

The flags are below. Only --profile and --url read an environment variable for their default:

FlagDefaultMeaning
--profile$DSH_SUPERAGENT_PROFILE, or superagentWhich DSH profile to control (scripts/dsh-superagent:212-213).
--url$DSH_SUPERAGENT_URL, or http://127.0.0.1:3082Where to read GET state for a health check (scripts/dsh-superagent:214-215).
--timeout60 secondsHow long start waits for the runtime to become ready (scripts/dsh-superagent:216).
--stop-timeout300 secondsHow long stop waits for a graceful shutdown, while running Executor Sessions finish their step (scripts/dsh-superagent:217-218).
--respect-stopoffFor a monitor: skip start or restart while an intentional stop is active (scripts/dsh-superagent:219-220, scripts/dsh-superagent:232-234).

status, start and restart share one exit-code scheme, computed by outcome() (scripts/dsh-superagent:112-119):

CodeMeaning
0The service runs normally: none of the other three conditions below held (scripts/dsh-superagent:118-119).
1It does not run, runs twice, does not answer, or its runtime health entry is not ready or paused (scripts/dsh-superagent:114-115, scripts/dsh-superagent:102-104). The script also exits with 1 on an error such as a start timeout (scripts/dsh-superagent:246-250).
2It runs, but some other part reports an error (scripts/dsh-superagent:118-119, scripts/dsh-superagent:107-109). A restart does not fix this.
3It runs and waits for setup (scripts/dsh-superagent:116-117). A restart does not fix this either.

The CLI reads GET state, a route that the panel also reads, with the same marker header, x-orchestrator-request: 1 (scripts/dsh-superagent:81-84, src/client/api.ts:37). The panel and the Management API: tabs, routes and settings versions covers why that header is required.

The Management API#

The panel and the Management API: tabs, routes and settings versions covers the loopback and same-origin checks, and how a save versions against one block. This table is the route list itself, from routes() (src/app/http.ts:151-214).

RequestWhat it does
GET stateSetup, health, load and pause state; read by the panel and by scripts/dsh-superagent status (src/app/http.ts:104-109, src/app/http.ts:156).
GET overviewThe Overview tab's summary (src/app/http.ts:157-158).
GET searchSearches Triggers, Threads and Tickets; it also matches a cached Feishu message link (src/app/http.ts:159, src/app/views/threads.ts:55-58).
GET sourcesEach Source's status and health, and the last day's filtered Triggers and dropped messages (src/app/http.ts:160, docs/006-deployment.md:173).
GET settingsEvery settings block, each Source instance, the Policy version and the execution environment (src/app/http.ts:161).
POST sources/:id/labelsReads one Source's display names again, such as Feishu chat names (src/app/http.ts:162, src/app/settings.ts:254-258).
GET threads, GET threads/:keyLists or opens one Thread's detail (src/app/http.ts:163-172).
POST threads/:key/unsubscribeRemoves every Ticket's Subscription to one Thread (src/app/http.ts:173-176, src/core/tickets.ts:214-218).
POST triggers/:id/requeueQueues a stored Trigger for a fresh Eval (src/app/http.ts:177-181).
GET decisions, POST decisions/:id/dismissLists Decisions, or dismisses one (src/app/http.ts:182-187).
GET tickets, GET tickets/:idLists Tickets, or one Ticket's full detail (src/app/http.ts:188-192).
POST tickets/:id/retry, POST tickets/:id/stopRetries or stops a Ticket, as the panel does (src/app/http.ts:193-194).
POST executor/pausePauses or resumes processing (src/app/http.ts:195).
PUT settings/:blockSaves one settings block against the revision it read (src/app/http.ts:196-202).
GET policy/historyPast Policy versions (src/app/http.ts:203).
POST policy-sync/:idRe-syncs one Source's allowed list now (src/app/http.ts:204).
POST setup/checkRestarts dsh-superagent to run setup again. It refuses when setup has nothing to fix (src/app/http.ts:205, src/app/setup.ts:54-57).
GET modelsThe model catalog a settings form's model picker reads (src/app/http.ts:206, src/client/settings-kit.tsx:74-82).
GET prompts, PUT promptsReads or saves the prompt configuration, against its own revision (src/app/http.ts:207-211).
POST prompts/previewComposes both roles' prompts without saving (src/app/http.ts:212).

A request needs the 127.0.0.1 or localhost host with the web server's port, the x-orchestrator-request: 1 header, and no foreign Origin (src/app/http.ts:75-79). A request that fails this check gets 403 (src/app/http.ts:237). Other refusals use a plain status code: 400 for an invalid request, 404 for something missing, 409 for a stale revision, 500 for anything else (src/app/http.ts:81-91).
