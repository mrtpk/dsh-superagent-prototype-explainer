dsh-superagent Explained

Code version: dsh-superagent @ 6337fc8 · 2026-10-31

dsh-superagent is a proactive coding agent for one GitHub repository, packaged as a bundle for DeepSeek Harness, DSH (README.md:7). It runs inside a DSH profile, as a set of Cordis plugins that its bundle file inserts (package.json:30-33, cordis.patch.yml:4-12). The sibling site, DeepSeek Harness Explained, teaches Cordis and DSH on their own. This site explains only what dsh-superagent adds on top of them. This site explains the code at commit 6337fc8. You need to know TypeScript and Node. You do not need to know this project's domain model yet: What dsh-superagent is teaches it.

What it doesListens to GitHub (and, optionally, Feishu); when an allowed person asks for work, it opens a Ticket and works on it in its own agent Session and directory (README.md:7).
Runs onNode.js, inside a DSH process, mainly as the Cordis plugin dsh-superagent, with one plugin for each Source (src/index.ts:7, cordis.patch.yml:4-12).
Code sizeTypeScript and TSX across src/, plus prompts and skills; the project has an unusually large test suite, indexed by its own test table (docs/007-architecture.md:402-405). See Code map: the folder tree.
Run itSetup has many steps, so a coding agent does it with you, following the repository's own SETUP.md (README.md:13-17).

The system map#

The map shows the main parts, and the order a GitHub event goes through them to become a Ticket and, later, a reply. Each title is a link. A grey link is a page not written yet.

  1. 1 · Source and Trigger — the GitHub Source polls and reads events, and turns each one into an immutable Trigger (src/sources/github.ts:280-296, src/sources/github-trigger.ts:65-77).
  2. 2 · Policy, gate and Eval — the gate checks who may ask for work, and Eval asks for an assessment of an admissible batch, which ends in a Decision (src/policy.ts:191-211, src/core/evals.ts:71-119).
  3. 3 · The Ticket — an accept Decision creates a Ticket under a Mandate, with its first Assignment (src/core/tickets.ts:37-56).
  4. 4 · The Executor — the Executor queues a launch for the Ticket. The launch starts one worker Session for the Ticket, in its own directory (src/executor/dsh.ts:1, src/executor/dsh.ts:263-266).
  5. 5 · The reply — a worker's report can send a reply back through a Channel, such as a GitHub comment (src/app/outbox.ts:27-32, src/sources/github-channel.ts:18-45).

Two parts sit beside every step, not inside the numbered path. A SQLite Store holds every Trigger, Thread, Decision, Ticket and Assignment the Engine writes (src/app/store.ts:1), and the durable Effects queue runs the launches, deliveries and replies each step enqueues (src/app/effects.ts:42-45). The React panel shows what needs a person (README.md:7, src/client/app.tsx:1).

Simplified

The map shows one Ticket's path once. It leaves out retries, resumes, Policy changes and the Feishu Source, which follows the same Source contract as GitHub. The tour Life of a GitHub mention: from a comment to a merged pull request follows one real path stop by stop.
