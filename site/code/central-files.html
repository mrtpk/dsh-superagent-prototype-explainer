The central files: a map of the files that carry the logic

Code mapabout 7 min read

Code version: dsh-superagent @ 6337fc8 · 2026-10-31

Purpose#

The folder tree lists every folder. This page picks the 19 files inside src/ that carry most of the project's own logic, and gives each one's size, role and main export. Every concept page on this site walks through some of these files in detail; this page is the map you come back to, not a replacement for reading them.

The domain core (src/core/)#

These seven files carry most of the domain core. The core imports no file outside src/core/; Code map: the folder tree lists the folder. Other folders import the core mainly through its barrel file, src/core/index.ts. The barrel exports all of model.ts and ports.ts, and selected names of seven other core files (src/core/index.ts:2-10).

FileLinesWhat it is
src/core/model.ts353The domain types and their small helper functions, independent of any Source, Policy or Executor (src/core/model.ts:1): Trigger (src/core/model.ts:23-39), Thread (src/core/model.ts:157-182), Ticket (src/core/model.ts:277-308), Mandate (src/core/model.ts:126-133), Decision (src/core/model.ts:190-209).
src/core/engine.ts270The Engine class (src/core/engine.ts:24): the single entry point of the core for each change to a Trigger, Thread, Decision, Ticket or Assignment (src/core/engine.ts:19-20). It also exports the role-scoped interfaces other layers receive, such as EngineForExecutor (src/core/engine.ts:269-270).
src/core/tickets.ts423The Tickets class (src/core/tickets.ts:29): a Ticket's life from an accept to its end, its Subscriptions and its Inputs. The largest file in the core.
src/core/evals.ts340The Evals class (src/core/evals.ts:27): the Thread-level assessment of queued Triggers, ending in a Decision.
src/core/assignments.ts140The Assignments class (src/core/assignments.ts:30) and the WorkerReport shape (src/core/assignments.ts:11-19): what the Executor and its workers report back, and when a Report ends the Ticket (src/core/assignments.ts:128-132).
src/core/intake.ts63The Intake class (src/core/intake.ts:16): Trigger ingestion, Thread correlation, Subscription fan-out, and Eval queuing, in that order.
src/core/ports.ts134The ports (interfaces) the Engine depends on, so the core never imports a Source, a Policy or an Executor directly: Policy (src/core/ports.ts:17-27), Assessor (src/core/ports.ts:49-53), Executor (src/core/ports.ts:59-69), Outbox (src/core/ports.ts:76-83) and Repositories (src/core/ports.ts:106).

Also in src/core/, each small enough that this page does not give it its own row: stage.ts, the stage machine (src/core/stage.ts:9-21, walked through step by step on The Ticket lifecycle: stages, Assignments and Subscriptions); replies.ts (the Replies part, src/core/replies.ts:26); part.ts (the shared EnginePart base class, src/core/part.ts); memory.ts (in-memory repositories for tests, src/core/memory.ts:1); the barrel index.ts; and three small support files, errors.ts, reasons.ts and ids.ts.

Policy (src/)#

src/policy.ts sits directly in src/, outside src/core/. The Policy it builds implements one of the Engine's ports (src/core/ports.ts:17-27). It is not part of the domain core.

FileLinesWhat it is
src/policy.ts242The settings schemas by block (PolicyConfigSchema, EvalConfigSchema, ExecutorConfigSchema, src/policy.ts:79-97), the Policy version (src/policy.ts:116-118), and settingsPolicy() (src/policy.ts:167-242), which builds the gate and Mandate revalidation covered on Policy and authorization: the gate, Eval and the Mandate it grants.

Two small files it depends on: src/admission.ts (13 lines, the admission table's own value type, src/admission.ts:9-13) and src/limits.ts (11 lines, the numeric bounds every settings schema checks against, src/limits.ts:2-11).

Execution (src/executor/)#

FileLinesWhat it is
src/executor/dsh.ts673The DshExecutor class (src/executor/dsh.ts:207), the only Executor this repository registers. It implements the Executor port from ports.ts, and also holds WorkerSlots (src/executor/dsh.ts:171-199), the concurrency limit covered on The Executor and worker Sessions: one Session per Ticket, a concurrency limit. The largest file in src/ outside src/client/.
src/executor/background.ts165Functions, not a class: runningJobs(), killJobs() and stopSubagents() manage a worker's shell jobs and subagents in DSH (src/executor/background.ts:1-3), called by dsh.ts, which also enforces the 30-minute background-work limit (src/executor/dsh.ts:32).

The app layer (src/app/)#

src/app/ is the glue: it gives the Engine its Store and ports, and gives the panel and the CLI a Management API. src/app/runtime.ts (254 lines) is its composition root: Runtime builds the Store (src/app/runtime.ts:98), the Settings (src/app/runtime.ts:126), the DshExecutor (src/app/runtime.ts:128) and the Sessions (src/app/runtime.ts:121), then registers the HTTP routes (src/app/runtime.ts:203). This page gives the six files it wires together their own rows; runtime.ts itself is mostly wiring, so it does not get one.

FileLinesWhat it is
src/app/store.ts291The Store class (src/app/store.ts:51), implementing the core's Repositories port: the one SQLite database behind every domain aggregate, the effect queue and the Outbox's receipts (src/app/store.ts:46-50).
src/app/effects.ts161The Effects class (src/app/effects.ts:46): the durable queue behind six effect kinds, such as launches, deliveries and replies, with exactly one handler per kind (src/app/effects.ts:11-24, src/app/effects.ts:67-68).
src/app/sessions.ts352The Sessions class (src/app/sessions.ts:93): lifecycle, prompt and tool decoration, message delivery and budget-retry tracking for both the main Session and worker Sessions. Also names the two agent presets, WORKER_PRESET and ROUTER_PRESET (src/app/sessions.ts:48).
src/app/prompts.ts247The Prompts class (src/app/prompts.ts:135) and promptParts() (src/app/prompts.ts:102-116): versioned role prompts, the fixed join order, and the two bundled Source skills, covered on Prompts and Source skills: how the system prompt is assembled.
src/app/settings.ts267The Settings class (src/app/settings.ts:82): block-scoped validation, optimistic-concurrency saves, and the processing-pause control.
src/app/http.ts247registerHttp() (src/app/http.ts:230-246) and routes() (src/app/http.ts:151-214): the loopback-only Management API every route of Configuration and deployment: the bundle, settings, env vars, the CLI and the API's route table comes from.

Also central to the app layer, without a row here because other pages already cite them in full: runtime.ts (above), context.ts (built-in prompt text, Prompts and Source skills: how the system prompt is assembled), outbox.ts and versions.ts (whole-object snapshot saving, Effects and the Store: a durable queue, and one writer per state and The panel and the Management API: tabs, routes and settings versions), and api.ts (the route table's shared types, read by both the server and the browser bundle, src/app/api.ts:1).

Source plugins (src/sources/)#

FileLinesWhat it is
src/sources/kind.ts115The SourceKind contract every Source implements (src/sources/kind.ts:85-113): its configuration schema, its admission-table rows and its outbound Channel adapter.
src/sources/github.ts459githubKind (src/sources/github.ts:38), one of the two SourceKinds this repository ships (the other is Feishu's): the GitHub Source's notification and repository polling loops, and its Cordis plugin entry, name = 'dsh-superagent-github' (src/sources/github.ts:110-112).

src/sources/registry.ts (138 lines) resolves one configured instance of an installed kind and routes an outgoing message to it (src/sources/registry.ts:50-53, src/sources/registry.ts:95-98); src/sources/feishu.ts (139 lines) is GitHub's counterpart for Feishu. Neither gets its own row: their role is the same shape as kind.ts and github.ts above.

The panel's data (src/client/)#

FileLinesWhat it is
src/client/locales.ts770The bilingual UI dictionaries the panel reads, as [zh, en] pairs that follow the domain terms of docs/001-domain.md (src/client/locales.ts:1-3). The largest file in src/. It is mostly data: it builds and exports two dictionaries, zh and en (src/client/locales.ts:751-752).

The panel's own structure, routes and six tabs are covered in full on The panel and the Management API: tabs, routes and settings versions, which cites src/client/index.tsx, route.ts and api.ts directly. This page does not repeat those files here.
